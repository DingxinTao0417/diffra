# t11-stock-negative

## 埋的问题

同一个订单「取消」和「全额退款」各放回一次占用的库存，两条路都走到时放了两次，`reserved` 变成负数或者吃掉别的订单的占用，可卖数量虚高，后面的订单超卖。先取消再退款、先退款再取消都会出。

原因在几个目录之间，单看一个文件看不出来：

- `src/orders/cancel-order.ts`：取消时直接调 `stock.release`，不管这单有没有退过款。
- `src/payments/refund-service.ts`：订单在什么状态都能退款，退完发 `payment.refunded`。
- `src/inventory/inventory-listeners.ts`：收到全额退款的 `payment.refunded`，只排除已发货的订单，然后调 `inventory.release`，不管这单有没有取消过。
- `src/inventory/inventory-service.ts`：`release` 只是按订单行把 `reserved` 减掉，不记这一单放没放过。

只取消、只全额退款各自是对的，可见测试里都有。`src/jobs/expire-unpaid-orders.ts` 也会放库存，但只处理没付款的订单，不会和退款撞上。

## 参考答案

`solution/` 只改 `src/inventory/inventory-service.ts`：记下哪些订单还占着库存，`release` 对同一单只生效一次，出库后也不再放。

## 试过的错误改法

每种都在原样项目的副本上改，再跑隐藏测试，全部失败（2026-11-12 实跑）：

| 改法 | 可见测试 | 隐藏测试 |
|---|---|---|
| W1 删掉退款事件里的 `release`（只退款不再放库存） | 失败 | 失败 3 个 |
| W2 删掉取消流程里的 `release`（只取消不再放库存） | 失败 | 失败 3 个 |
| W3 退款事件里多排除已取消的订单（只修了「先取消再退款」） | 通过 | 失败 4 个 |
| W4 `reserved` 不许小于 0（别的订单还占着库存时照样多放） | 通过 | 失败 1 个 |
| W5 取消时跳过已全额退款的订单（只修了「先退款再取消」） | 通过 | 失败 4 个 |

另外确认了一种不同的正确改法也能通过：W3 和 W5 一起做（两个方向都按状态判断）。

「先全额退款再取消」的用例不判取消这一步成不成功，只看库存，所以把这种取消拒掉的改法只要库存对也算过；「先取消再全额退款」要求退款成功，取消了的订单钱必须能退。
