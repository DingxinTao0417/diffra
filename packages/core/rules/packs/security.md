## 访问控制
- [SEC-AUTH-1][强制] 属于用户个人的数据和操作，服务端要校验当前用户有没有权限，不能只凭请求里传来的 id（防越权）。
- [SEC-AUTH-2][强制] 接口默认需要登录和权限校验，只有确实要公开的才放开；不靠前端隐藏按钮做权限控制。

## 输入与注入
- [SEC-INJ-1][强制] SQL 用参数绑定或 ORM 的参数化方法，不拼接外部输入；动态的表名、列名、排序字段用白名单。
- [SEC-INJ-2][强制] 不把外部输入拼进 shell 命令、eval、new Function 或模板；需要执行外部命令时用参数数组并限制可执行的命令。
- [SEC-INJ-3][强制] 外部输入都要校验类型、长度、范围和格式，不通过就拒绝；分页大小、批量条数要设上限。
- [SEC-INJ-4][强制] 由外部输入决定的文件路径要规范化后确认仍在允许的目录内，拒绝 .. 路径穿越。
- [SEC-INJ-5][推荐] 用正则校验外部输入时避免可能回溯爆炸的写法（ReDoS），并先限制输入长度。
- [SEC-INJ-6][推荐] 不反序列化不可信的数据；解析 XML 时关闭外部实体（XXE）。

## 输出
- [SEC-OUT-1][强制] 把外部数据放进 HTML 要按所在位置转义；不用 innerHTML、v-html、dangerouslySetInnerHTML 输出未经过滤的内容。
- [SEC-OUT-2][强制] 手机号、证件号、银行卡号、地址等个人信息在服务端脱敏后再返回；密码、密保答案不存储也不展示明文。
- [SEC-OUT-3][推荐] 响应的 Content-Type 与实际内容一致，并设置 X-Content-Type-Options: nosniff 等安全响应头。
- [SEC-OUT-4][推荐] 生产环境的错误响应不返回堆栈、SQL、文件路径和内网地址；关闭框架的调试模式。

## 请求
- [SEC-REQ-1][强制] 使用 cookie 会话的表单和接口要有 CSRF 防护；CORS 的 Origin 用完全匹配校验。
- [SEC-REQ-2][强制] 重定向目标、服务端代为请求的 URL 用白名单校验协议和域名，拒绝内网地址（防 SSRF）。
- [SEC-REQ-3][强制] 短信、邮件、下单、支付这类消耗资源的接口要防重放和限频，比如次数限制和验证码。
- [SEC-REQ-4][强制] 上传文件限制类型（白名单）和大小，用随机名称存储，不放进可执行的 Web 目录。
- [SEC-REQ-5][推荐] 发帖、评论等用户生成内容的接口要防刷，并过滤违禁内容。

## 密钥与密码
- [SEC-KEY-1][强制] 密码、密钥、令牌、数据库账号不写进代码和提交到仓库的配置，从环境变量或密钥管理服务读取。
- [SEC-KEY-2][强制] 用户密码用加盐的慢哈希（bcrypt、scrypt、Argon2）存储，不用明文、可逆加密、MD5 或 SHA-1。
- [SEC-KEY-3][推荐] 令牌、验证码等安全相关的随机值用密码学安全的随机数生成器。
- [SEC-KEY-4][推荐] 对称加密用 AES 等现行算法，不用 DES、3DES；网络请求优先用 HTTPS。
- [SEC-KEY-5][推荐] 登录态 cookie 设置 HttpOnly 和 Secure。
